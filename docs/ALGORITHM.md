# 德育分计算算法说明

> 本文档完整描述西安交通大学综合素质测评（德育分）的计算规则与算法实现。
> 评分依据：《本科生专业选择综合素质测评内容及评分标准》。

## 总体结构

总分 = 品行素质分（80） + 能力拓展分（20） + 奖励分（5） = 满分 **105 分**

```
总分 S = max(0, min(105, S_conduct + S_ability + S_reward))
```

各模块独立计算并先行封顶，再相加得到总分。

---

## 一、品行素质分（满分 80）

### 计算公式

```
S_conduct = clamp_0_80( base + collective + political + social - penalty )
```

其中 `clamp_0_80(x) = max(0, min(80, x))`。

### 各分项规则

| 分项 | 上限 | 计算规则 |
|------|------|----------|
| 基准分 `base` | 70 | 班级评议合格 + 书院审定通过 → 70；否则 0 |
| 集体活动 `collective` | 3 | 见下方分模式说明 |
| 思政学习 `political` | 3 | 基础学习(+1) + 省部级培训(+2) + 突出表现(+1)，封顶 3 |
| 社会服务 `social` | 4 | 见下方累加规则 |
| 扣分 `penalty` | 不限 | Σ 各处分类型分值 × 数量 |

### 集体活动（双模式）

```
# 模式 1：按次累加
collective_raw = collectiveCount × collectivePerActivity   # 默认 0.3 分/次

# 模式 2：手动输入
collective_raw = collectiveManual

# 模式 3：突出贡献（直接给上限）
if collectiveOutstanding: collective_raw = 3

collective = clamp_0_3(collective_raw)
```

### 社会服务（线性 + 累加）

```
social_volunteer = min(1, volunteerHours / 32)        # 32 志愿时换 1 分，封顶 1
social += socialPractice ? 1 : 0                      # 社会实践 +1
social += internLevel == "city"     ? 1 : 0           # 市级挂职 +1
social += internLevel == "province" ? 2 : 0           # 省级挂职 +2
social += advancedIndividual ? 1 : 0                  # 先进个人 +1
social = min(4, social)                               # 封顶 4
```

### 扣分项查表

| 处分类型 | 扣分 |
|---------|------|
| 通报批评 | 2 |
| 警告处分 | 4 |
| 严重警告处分 | 6 |
| 记过处分 | 8 |
| 留校察看处分 | 10 |
| 旷课（未达处分） | 1 / 次 |
| 宿舍卫生不合格 | 1 / 次 |

### 算例

> 学生 A：通过班级评议，参加 8 次集体活动，完成基础思政 + 省部级培训，志愿服务 64 小时 + 一次社会实践，无处分。

```
base       = 70
collective = min(3, 8 × 0.3) = 2.4
political  = min(3, 1 + 2)   = 3
social     = min(1, 64/32) + 1 = 2
penalty    = 0
S_conduct  = clamp(70 + 2.4 + 3 + 2 - 0) = 77.4
```

## 二、能力拓展分（满分 20）

### 计算公式

```
S_ability = min(20, S_academic + S_artSport + S_org)
```

三个子项**先各自封顶**再求和，求和后再总封顶。

### 2.1 学术科研（封顶 10）

```
S_academic = min(10, Σ 竞赛得分 + Σ 论文/专利得分)
```

#### 学科竞赛二维查表

```
score(level, award) = ACADEMIC_COMP[level][award]
```

| 等级\奖项 | 特等/一等 | 二等 | 三等 | 优秀奖 |
|----------|----------|------|------|--------|
| 国际/国家级 | 10 | 9 | 8 | — |
| 省级 | 8 | 6 | 4 | — |
| 校级/地方/行业 | 4 | 3 | 2 | 1 |

> **业务规则**：同一项目取最高，不同项目累加 → 由用户决定输入哪些条目，算法只做累加。

#### 论文/专利（按作者排名分级）

```
score(type, authorRank) = PAPER_SCORES[type].scores[min(authorRank-1, 3)]
# 专著特殊处理：authorRank > 3 时 score = max(1, 6 - (authorRank - 3))
# 优秀论文 +1
```

| 类型 | 1 作 | 2 作 | 3 作 | 4 作及以后 |
|------|------|------|------|-----------|
| 国际期刊论文 | 10 | 8 | 6 | 2 |
| 国内核心/国际会议 | 6 | 5 | 4 | 1 |
| 国内一般期刊/会议 | 3 | 2 | 1 | 0 |
| 出版专著 | 10 | 8 | 6 | 阶梯递减最低 1 |
| 发明专利 | 10 | 8 | 6 | 2 |
| 实用新型/软著 | 6 | 5 | 4 | 1 |

### 2.2 文体竞赛（封顶 6）

```
S_artSport = min(6, Σ 文艺得分 + Σ 体育得分 + 破纪录加分)
```

文艺竞赛二维查表（`level × award`），体育竞赛二维查表（`level × rank`）。

| 破纪录类型 | 加分 |
|-----------|------|
| 破省级及以上纪录 | 5 |
| 破校级纪录 | 3 |
| 未破纪录 | 0 |

### 2.3 组织任职（封顶 4，**取最高，不累加**）

```
S_org = min(4, ORG_LEVELS[level].scores[rating])     # 仅最高一个职务
```

| 级别 | 优 | 良 | 合格 |
|------|-----|-----|------|
| 一级（校学生组织正职等） | 4 | 3.5 | 3 |
| 二级（院级正职/校副职等） | 3.5 | 3 | 2.5 |
| 三级（部长/班长/团支书等） | 2 | 1.5 | 1 |
| 四级（干事/宿舍长等） | 1 | 0.75 | 0.5 |

> **核心难点**：与学术/文体的累加规则不同，组织任职是**取最高一职**——这是常见误算点。

### 算例

> 学生 B：国家级二等奖一项 + 省级三等奖一项 + 1 作国内核心论文一篇 + 校三等文艺奖一项 + 校二级班长（优）。

```
S_academic = min(10, (9 + 4) + 6) = 10                 # 触发上限
S_artSport = min(6, 1 + 0 + 0)    = 1
S_org      = ORG_LEVELS[2]["excellent"] = 2
S_ability  = min(20, 10 + 1 + 2)  = 13
```

## 三、奖励分（满分 5）

### 计算公式

```
S_reward = min(5, Σ 荣誉得分 + 好人好事)
```

### 荣誉表彰查表

| 级别 | 单条加分 |
|------|---------|
| 全国级 | 5 |
| 省级 | 4 |
| 市级 | 3 |
| 校级 | 2 |
| 院级 | 1 |

> 一条全国级即触顶；好人好事按事件数累加（视情况酌情认定，工具不强制约束）。

## 四、关键业务规则总结

| 规则 | 触发位置 | 说明 |
|------|---------|------|
| **取最高 vs 累加** | 学科竞赛、文艺、体育按"同项目取最高、跨项目累加"；组织任职**仅最高一职** | 由用户决定输入条目（取最高），算法做求和（累加） |
| **二维查表** | 学科竞赛 = level × award；文艺/体育 = level × award/rank | 双 key 查表，未匹配返回 0 |
| **阈值分段** | 论文作者排名按 1/2/3/≥4 分四档；专著 ≥4 作时按 `max(1, 6 - (rank-3))` 阶梯递减 | 边界值需精确处理 |
| **多层封顶** | 各子项先封顶 → 子项之和再封顶 → 总分再封顶（理论 105，实际由各模块上限保证） | 顺序不可颠倒 |
| **线性映射** | 志愿时数 / 32 → 1 分（封顶） | 32 小时挡位 |

## 五、目标分推荐器算法（拓展）

> 在基础计算之外，本项目额外实现了"目标分反向推荐"功能。详见 [src/algorithms/recommender.js](../src/algorithms/recommender.js)。

### 问题建模

给定当前已有得分 `S_now` 与目标得分 `S_target`，求**最少努力代价**的加分组合。

```
变量：x_i ∈ {0, 1}    (是否采纳第 i 个加分项建议)
约束：Σ value_i × x_i ≥ S_target − S_now
     各封顶组约束：Σ_group ≤ cap_group
目标：min Σ cost_i × x_i
```

> **封顶组（cap group）的粒度**：品行内部的集体活动（3）/ 思政学习（3）/ 社会服务（4）各自独立封顶，与能力的学术（10）/ 文体（6）/ 任职（4）一样按子项分别背包——共 7 个封顶组。
> 若把整个品行当成一个 `80 − S_conduct` 的大桶，会出现"思政子项已满、品行整体仍有余量 → 仍推荐思政项（实际加 0 分）"的错误。子项分别封顶后，`70 + (集体+思政+社会 ≤ 10) = 80`，与"品行 ≤ 80"严格等价。

`cost_i` 为该加分项的"努力代价"权重（如：志愿时数、竞赛准备时间），由经验估值给出。

### 算法选择

- **0/1 背包动态规划**：精确求解，时间 O(N·W)，N 为候选项数，W 为分差刻度（× 10 以处理 0.1 精度）
- **贪心算法**：按 `value_i / cost_i` 降序选择，时间 O(N log N)，作为对照与近似解

### 复杂度对比

| 算法 | 时间 | 空间 | 最优性 |
|------|------|------|--------|
| 0/1 背包 DP | O(N·W) | O(W) 滚动数组 | 全局最优 |
| 贪心 | O(N log N) | O(1) | 近似（性价比启发式） |

实测：典型场景 N≈30，W≈300（30 分差 × 10 精度），DP 约 0.2ms，贪心约 0.05ms。两者差距在 UI 上不可感知，但 DP 解的准确性更优——尤其在临近上限的"刚好够用"场景下，贪心可能多选 1-2 项造成浪费。

### 现状感知与约束修正

推荐器直接读取计算器里**已实际录入的明细状态**（而非仅聚合分），据此做三类修正，避免推荐"做了也不增分"的无效项：

1. **自动跳过已完成的一次性项**（`achievedCandidateIds`）：思政三项、志愿满 32h、社会实践、挂职、社会服务先进个人、破纪录等"布尔/阈值型"项，一旦在计算器里已勾选/已达阈值，就不再推荐——它们再做一次也不增分。竞赛、论文、荣誉、好人好事等**可累加**项不在此列，可继续叠加至封顶。
2. **前置依赖守卫**（`isCandidateAvailable`）：思政"优秀学员"需先参加培训、社会服务"先进个人"需先参加任一服务，否则按规则实际算 0 分；前置未满足时不推荐这些"额外加分"项。
3. **组织任职替换建模**（`prepareCandidates`）：任职是"取最高一职、不累加"，故候选项的真实价值是**相对当前任职分的净增** `value' = max(0, value − S_org_now)`；净增 ≤ 0（同级/更低职务）直接丢弃。配合"任职互斥（最多选一项）"，即可正确表达替换语义，并使展示的 `+value` 与实际增量保持诚实。

> 此外，「我的现状」问卷作为**可选的上限偏好**保留：对竞赛/论文/荣誉等可累加维度，声明"不超过某档位"以收窄推荐范围（如已任三级则不再推荐一/二级）。它与上面的自动现状感知互补——前者是用户主动偏好，后者是从录入数据自动推导的客观事实。

详细推导与实测数据见 [实验报告.md](../实验报告.md) 第八章。
